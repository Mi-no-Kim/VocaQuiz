## 이슈 1

**제목:** `[Decision] 원제 언어(original_language) 개념을 없앨지`
**라벨:** decision

```markdown
## 상황

commit 6·7(곡 만들기·편집 화면)을 실사용해보니 "원제 언어"가 따로 필요 없어
보인다 — 원제 언어가 하던 역할(그 곡이 어느 언어 곡인지)은 이미 `song_language`
(곡 언어 다중선택)가 채우고 있다. 지금은 `song.original_language_id`가 별도
컬럼으로 있고, `song_language`와 완전히 독립적으로 고른다(자동으로 안 채워짐).

## 관련 결정

- D-061(대표 이름은 언어마다 1개, 원제 언어는 필수) — 원제 언어 자체가 없어지면
  "원제 언어에는 대표 이름이 반드시 있다"는 조건을 무엇으로 대체할지 다시 봐야 함.
- D-062(PUBLISHED 조건 1번 "원제 언어의 대표 이름") — 같은 이유로 조건 문구를
  다시 봐야 함.
- B3(원제 언어와 song_language는 완전히 별개, D-번호 없는 세션 내 결정) — 원제
  언어가 없어지면 이 결정 자체가 없어짐.

## 선택지

| 선택지                                                                                         | 비용                                                                                                                                                                                                                                                                     | 채택 |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---- |
| A. `original_language_id` 완전히 제거, `song_language` 중 아무 언어에나 이름을 붙일 수 있게 함 | 스키마 마이그레이션(컬럼 제거), 기존 곡 데이터 이행 필요. D-061의 "대표 이름 1개 필수" 조건을 "언어 하나엔 반드시 있어야 한다"에서 어떻게 다시 정할지부터 결정해야 함 — 지금은 원제 언어가 그 최소 보장 역할을 함. commit 6·7 프론트(원제 언어 select·필수 검증) 재작업. |      |
| B. 컬럼은 남기되 "원제 언어" 대신 "대표 언어"로 이름만 바꾸고 song_language에 자동 포함시킴    | 스키마는 안 건드림. 다만 "그래도 언어를 하나 더 골라야 한다"는 중복 느낌은 그대로 남을 수 있음.                                                                                                                                                                          |      |
| C. 그대로 유지                                                                                 | 재작업 없음. 민호님이 이미 불필요하다고 본 개념을 계속 둠.                                                                                                                                                                                                               |      |
```

## 이슈 2

**제목:** `[Decision] 프로듀서 이름을 언어별로 관리할지`
**라벨:** decision

```markdown
## 상황

commit 6·7을 실사용해보니 프로듀서 이름을 언어별(번역명)로 넣고 싶다는 요구가
나왔다. 지금은 `producer.name`이 언어 구분 없는 단일 UNIQUE 문자열이다(D-063).

## 관련 결정

- D-063(프로듀서 이름은 유일하다) — 언어별 이름을 허용하면 "유일함"의 기준이
  프로듀서 전체 하나의 이름인지, 언어별 이름인지 다시 정해야 함.

## 선택지

| 선택지                                                                                                         | 비용                                                                                                                                                                                             | 채택 |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---- |
| A. `song_name`과 같은 패턴으로 `producer_name` 테이블 신설(프로듀서 1:N, 언어별 이름)                          | 새 테이블·리포지토리·서비스 필요. 자동완성 검색이 여러 언어 이름을 다 훑어야 함. UNIQUE를 어느 범위로 둘지(프로듀서 전체 vs 언어별) 다시 정해야 함. 프론트 프로듀서 검색·생성·칩 UI 전부 재작업. |      |
| B. `producer.name`(원어 표기)은 유지, 번역 표시용 보조 테이블만 추가하고 자동완성 대상은 원어 이름 하나로 유지 | 스키마 변경 폭이 작음. 다만 번역명으로는 검색이 안 됨.                                                                                                                                           |      |
| C. 그대로 유지(원어 표기 하나만)                                                                               | 재작업 없음.                                                                                                                                                                                     |      |
```
